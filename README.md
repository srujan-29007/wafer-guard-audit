# WAFER-GUARD: Fab-7 Excursion Detector (Audit and Repair)

Audit and repair of a PyTorch supervised-autoencoder notebook that detects defective wafers in SECOM-style telemetry. The original notebook reported F1 ≈ 0.99, but that number came from a leaky pipeline and an artificially balanced test set. This repository contains the corrected pipeline and an honest evaluation at natural defect prevalence.

**Recommendation: NO-GO.** See [`AUDIT.md`](AUDIT.md) for the full findings.

## Repository contents

| File | Description |
|---|---|
| `wafer_guard_fixed.ipynb` | Corrected end-to-end notebook: diagnostics, repaired pipeline, training, evaluation, artifact export |
| `AUDIT.md` | Findings ranked by severity, metrics, residual risks, go/no-go (generated by the last notebook cells) |
| `test_metrics.json` | Final test-set metrics from the notebook run |
| `artifacts/` | Created by the notebook: model weights and preprocessing/threshold bundle |

The dataset `secom_telemetry_modified.csv` is not included in this repo; place it next to the notebook (see below). The evaluator-only legacy mask file is **not used anywhere** in the pipeline. Legacy wafers are detected from the data itself (`sensor_0 == 0.0`).

## How to run

**Prerequisites:** Python 3.10+, and the packages `torch>=2.2`, `scikit-learn>=1.2`, `imbalanced-learn>=0.11`, `pandas`, `numpy`, `joblib`, `matplotlib`.

1. Put `secom_telemetry_modified.csv` in the same folder as the notebook.
2. Open `wafer_guard_fixed.ipynb` in Jupyter or Google Colab.
3. Run all cells from a fresh kernel. The first cell installs dependencies. In Colab, if the CSV is missing you will be prompted to upload it.
4. Outputs: `test_metrics.json`, `AUDIT.md`, and `artifacts/wafer_guard_model.pt` plus `artifacts/preprocessing_and_threshold.joblib`.

Runs on CPU; seed is fixed (`SEED = 1337`).

## What was wrong and how it was fixed

| # | Defect | Mechanism | Repair |
|---|---|---|---|
| 1 | Data leakage | Imputer, scaler and SMOTE were applied to all rows before the split, so the test set contained synthetic and training-derived points (test prevalence forced to 50%) | Chronological split; imputer and scaler fit on train only; no resampling of validation or test; class imbalance handled with `pos_weight` in the loss |
| 2 | Corrupted loss gradients | Input had shape `[B, 1, F]` while the reconstruction was `[B, F]`, so the MSE silently broadcast to `[B, B, F]` | Inputs kept as `[B, F]`; shape assertions in `forward` and in the training loop |
| 3 | Legacy PS-L invariants ignored | `sensor_0 == 0.0` sentinel and categorical `sensor_1` codes (100/200/300) were mean-imputed and scaled as continuous values | `is_legacy` flag plus one-hot `code_100/200/300`; legacy `sensor_0`/`sensor_1` masked to NaN before continuous imputation and scaling |
| 4 | Random split ignores time | Stratified random split lets future wafers influence predictions on the past | 60/20/20 split by timestamp |
| 5 | Fixed 0.5 threshold on a balanced test set | Threshold and metrics were meaningless at 6.6% prevalence | Threshold chosen on validation only (max F1), frozen, applied once to the untouched test set |

Additional handling: train-constant columns are dropped (122 columns), the best epoch is selected by validation PR-AUC, and the notebook includes diagnostic cells that show the broadcast shapes, the preprocessing-statistic differences, and the effect of the sentinel values.

For comparison, the original notebook's reported metrics (F1 0.9915, precision 0.9832, recall 1.0000, from a 50%-prevalence test set contaminated by SMOTE-before-split) are **invalid** and are kept only to document the failure.

## Limitations

- Only 104 defects in total: the test set has 17 and the validation set 11. All metrics, and especially the validation-selected threshold, are noisy. No confidence intervals are reported.
- The model shows little skill. Test PR-AUC is only modestly above the base rate, and validation PR-AUC (0.0328) is below the validation defect rate (0.0351), so the early selected epoch and the threshold are effectively noise. At the chosen threshold, about 51% of test wafers (161 of 314) are flagged.
- Temporal drift is present and only a single chronological split was evaluated; no rolling backtest was run.
- The legacy subset is small (146 of 1567 wafers) and contains no defects, so `is_legacy` acts as a strong "pass" indicator. Other channels (`sensor_390`, `sensor_252`) also differ strongly for legacy wafers and are not specially handled.

## Notes

- The original-notebook baseline numbers are hard-coded from a separate run, not recomputed in the repaired notebook. The leakage diagnostics in the repaired notebook use logistic regression, not the autoencoder.
- `AUDIT.md` is regenerated by the last cells of the notebook; edit the text there if you rerun, or the file will be overwritten.

## Reproducibility note

Reported numbers are the actual outputs of the notebook run stored in `test_metrics.json`. If you rerun on different hardware or library versions, small numerical differences are possible.
